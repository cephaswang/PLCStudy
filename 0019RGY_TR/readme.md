實作題2：紅綠燈交通號誌控制（簡化版）－ 程式說明文件
機型：三菱 FX5CPU / FX5U　開發軟體：GX Works3
語法：LD（梯形圖 / 指令表）
版本：v1.3 － X0_TRIG 改為一般繼電器（電位判斷），不使用上升緣偵測(ORP/R_TRIG)
================================================================

一、程式功能概述
----------------------------------------------------------------
本程式模擬簡化版十字路口紅綠燈控制。以 X0 作為運轉開關（維持型），
X0=ON時系統開始運轉，並依「綠燈→黃燈→紅燈→綠燈」順序無限循環；
X0=OFF時系統停止，所有燈號熄滅，計時器歸零。

二、輸出入及內部元件配置
----------------------------------------------------------------
X0        啟動開關（維持型接點，ON=運轉，OFF=停止）
Y0        綠燈輸出
Y1        黃燈輸出
Y2        紅燈輸出
M0        綠燈階段旗標
M1        黃燈階段旗標
M2        紅燈階段旗標
X0_TRIG   開機起動旗標（一般輔助繼電器，非邊緣偵測型）
T0        黃燈計時器，設定值 K50（5.0秒）
T1        紅燈計時器，設定值 K20（2.0秒）
T2        綠燈計時器，設定值 K50（5.0秒）

三、程式邏輯說明（依掃描順序）
----------------------------------------------------------------
【第0段】X0_TRIG 起動旗標
　LD X0 / ANI M0 / ANI M1 / ANI M2 / OUT X0_TRIG
　說明：當 X0 導通，且 M0、M1、M2 三個階段旗標皆為前次掃描值0
　（即系統尚未進入任何燈色階段）時，X0_TRIG 才會導通。
　一旦 M0 於本次掃描被驅動為ON，下一掃描 ANI M0 條件即不成立，
　X0_TRIG 隨即自動斷路。此設計以「電位條件」取代原本的
　ORP X0（上升緣偵測）／R_TRIG函數方塊，效果等同單次啟動脈波，
　但不占用邊緣偵測指令，且不需額外的函數方塊型別標籤。

【第1段】綠燈階段旗標 M0
　LD T2 / OR M0 / OR X0_TRIG / ANI M1 / AND X0 / OUT M0
　說明：當「紅燈計時器T2計時到」或「M0自保持」或「X0_TRIG起動旗標
　導通」時，且目前非黃燈階段（M1=OFF）、系統運轉中（X0=ON），
　則驅動M0導通，進入綠燈階段。

【第2段】黃燈階段旗標 M1
　LD T0 / OR M1 / ANI M2 / AND X0 / OUT M1
　說明：當「綠燈計時器T0計時到」或「M1自保持」時，且目前非紅燈
　階段（M2=OFF，取前次掃描值）、系統運轉中，則驅動M1導通，
　進入黃燈階段。

【第3段】紅燈階段旗標 M2
　LD T1 / OR M2 / ANI M0 / AND X0 / OUT M2
　說明：當「黃燈計時器T1計時到」或「M2自保持」時，且目前非綠燈
　階段（M0=OFF，取本次已更新值）、系統運轉中，則驅動M2導通，
　進入紅燈階段。

【第4段】燈號輸出
　LD M0 / OUT Y0（綠燈）
　LD M1 / OUT Y1（黃燈）
　LD M2 / OUT Y2（紅燈）
　說明：三個階段旗標分別直接驅動對應的燈號輸出。

【第5段】計時器
　LD M0 / OUT T0 K50（綠燈計時5.0秒，計滿驅動黃燈M1）
　LD M1 / OUT T1 K20（黃燈計時2.0秒，計滿驅動紅燈M2）
　LD M2 / OUT T2 K50（紅燈計時5.0秒，計滿驅動綠燈M0）
　說明：各計時器僅在對應階段旗標導通時開始計時，離開該階段
　（旗標OFF）時，計時器IN條件消失，經過值ET自動歸零。

四、動作時序說明
----------------------------------------------------------------
1. X0 由 OFF 轉為 ON：
　此時 M0、M1、M2 皆為0，X0_TRIG 本次掃描判定為TRUE，驅動M0
　導通，Y0（綠燈）亮起，T0開始計時。下一掃描M0已為ON，
　X0_TRIG 隨即自動歸零，不會持續輸出。

2. 綠燈階段（M0=ON）持續5.0秒：
　T0計時到後，M1導通，M0因 ANI M1 條件不成立而斷路，
　Y0熄滅、Y1（黃燈）點亮，T1開始計時，T0因M0=OFF而歸零。

3. 黃燈階段（M1=ON）持續2.0秒：
　T1計時到後，M2導通，M1因 ANI M2 條件不成立而斷路，
　Y1熄滅、Y2（紅燈）點亮，T2開始計時，T1因M1=OFF而歸零。

4. 紅燈階段（M2=ON）持續5.0秒：
　T2計時到後，M0導通（透過 OR M0 自保及 LD T2 條件），M2因
　ANI M0 條件不成立而斷路，Y2熄滅、Y0（綠燈）點亮，T0重新
　開始計時，T2因M2=OFF而歸零。如此循環往復，形成
　綠→黃→紅→綠…的無限循環。

5. X0 由 ON 轉為 OFF：
　M0、M1、M2 皆因 AND X0 條件不成立而全部斷路，Y0/Y1/Y2
　全部熄滅，T0/T1/T2 因IN條件消失而經過值歸零，X0_TRIG亦
　因X0=OFF同步斷路。系統回到停止狀態，等待下次X0導通時
　重新從綠燈階段啟動。

五、與原ORP X0（上升緣偵測）版本之差異
----------------------------------------------------------------
原版使用 ORP X0（或ST版之R_TRIG函數方塊）在X0上升緣產生單一
掃描週期的TRUE脈波，用以驅動M0首次導通。

本版改用 X0_TRIG = X0 AND (M0、M1、M2均為OFF) 的電位條件達成
相同效果：只要系統從停止狀態（三旗標皆OFF）轉為X0導通，
X0_TRIG就會在該次掃描產生單一脈波效果（下一掃描因M0已導通而
自動歸零），因此對外部行為完全相同，但改用一般輔助繼電器
（BOOL / 一般接點型）即可實現，不需要邊緣偵測指令或R_TRIG
函數方塊，亦不受限於函數方塊之標籤型別設定，可直接於一般
LD程式或不支援R_TRIG的機型上使用。
